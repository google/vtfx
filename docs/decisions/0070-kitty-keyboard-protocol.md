# The kitty keyboard protocol

- Status: Approved (2026-10-23, approved by a human, who asked for the protocol and chose flags 1 and 4, the unshifted key and the key of the base layout in `KeyStroke`, the stacks behaving as kitty's, the keypad following NumLock, and no option to turn the protocol off; the other details were proposed by an agent)
- Date: 2026-10-23
- Related: Requirement 6.1, section 2 of [gate-policy.md](../design/gate-policy.md), section 3 of [emulation.md](../design/emulation.md), section 7.1 of [compose-input.md](../design/compose-input.md), section 6.3 of [ime-contract.md](../design/ime-contract.md), [0005](0005-key-bytes-through-gate.md), [0079](0079-emulation-scope.md)

## Background

The legacy encoding of keys is ambiguous: Esc is the first byte of every escape sequence, so programs tell a lone Esc from Alt and a key by waiting; Ctrl+I is Tab, Ctrl+M is Enter, and Ctrl+Shift+A is Ctrl+A; Shift+Enter and Ctrl+Enter are Enter. The kitty keyboard protocol (<https://sw.kovidgoyal.net/kitty/keyboard-protocol/>) lets a program ask for unambiguous encodings, in steps that it chooses with flags: 1 disambiguates the escape codes, 2 reports repeats and releases, 4 reports the shifted key and the key of the base layout, 8 reports every key as an escape code, even keys that produce text, and 16 adds the text to those escape codes. The program pushes its flags on a stack when it starts and pops them when it exits, and queries them to learn which the terminal supports. Vim, Neovim, Helix, kakoune, fish, and nushell use it; most ask for flag 1, some for 1 and 4.

[0079](0079-emulation-scope.md) left the keyboard protocols to a decision of their own, because they change the bytes that the gate sends for keys, which [0005](0005-key-bytes-through-gate.md) limits to what xterm encodes. A human asked for the kitty keyboard protocol on 2026-10-23.

vtfx does not see keys the way a desktop terminal does. Characters that the user types reach the host as text through the IME editing model, from soft keyboards, which send no key events, and from hardware keyboards alike (section 6.3 of [ime-contract.md](../design/ime-contract.md)); corrections of the IME are sent as DELs. `KeyStroke` described a key pressed down, with the character it produces after Shift, and nothing about releases, repeats, the unshifted key, or the physical key. The terminals that implement the protocol all report the unshifted key of the layout, so that Ctrl+Shift+1 is the `1` key with Shift and Ctrl; all of them but vtfx implemented every flag.

## Decision

1. **The flags are kept as kitty keeps them.** `CSI = flags ; mode u` sets, adds, or removes flags (mode 1, the default, 2, or 3; other modes, 0 among them, change nothing), `CSI > flags u` pushes, `CSI < n u` pops n entries (one if n is omitted; 0 pops none), and `CSI ? u` is answered with `CSI ? flags u`. Each screen has its own stack, as the protocol requires, so that a program on the alternate screen does not change the flags of the shell on the main screen. A stack holds 8 entries, and a push onto a full stack drops the oldest. Popping every entry clears the flags. RIS and DECSTR empty both stacks.
2. **Flags 1, disambiguate escape codes, and 4, report alternate keys, are supported.** The stacks keep only the flags that vtfx supports, so that the reply to `CSI ? u` tells the program what vtfx does, which is how the protocol says programs detect a terminal that implements part of it.
3. **The others are not supported, for these reasons:**
   - Flag 2 needs the releases and repeats of keys, which `KeyStroke` does not describe and soft keyboards do not send.
   - Flags 8 and 16 need every key as an escape code, but typed characters reach the host as text through the IME editing model, and soft keyboards send no keys at all. Setting the flags while sending text would mislead the program.
4. **Under flag 1, keys are encoded as kitty encodes them** (section 2.2 of [gate-policy.md](../design/gate-policy.md)): Esc as `CSI 27 u`; Enter, Tab, and Backspace with modifiers as `CSI u` and without them as in the legacy encoding, so that a user can still type `reset` after a program left the flag set; character keys with Ctrl, Alt, or Meta as `CSI code ; modifiers u`; the other keys in the `CSI 1 ; modifiers letter` and `CSI number ; modifiers ~` forms. DECCKM and DECKPAM no longer give SS3 forms, as in kitty. Meta is the protocol's Super, which has the same bit as Meta in xterm's parameter.
5. **`KeyStroke.Character` carries the unshifted key and the key of the base layout.** The code of a character key is its unshifted key, the character that the key produces without modifiers, so that Ctrl+Shift+A is `CSI 97 ; 6 u` and Ctrl+Shift+1 is `CSI 49 ; 6 u`. Shift is reported as a modifier when it is held, which the legacy encoding ignores for characters. `KeyEventHandler` in vtfx-compose takes the unshifted key from the key character map of the keyboard, and the key of the base layout, the key at the same place on a US PC-101 keyboard, from the scan code. The key bars of apps give both themselves; a key that has no place on a keyboard, such as the first character of text that the IME commits while sticky modifiers are armed, takes its character in lower case as the unshifted key and has no key of the base layout. The lock keys are not reported, since `KeyModifiers` has none: kitty, Ghostty, WezTerm, and foot report Caps Lock and NumLock, and Alacritty and xterm.js do not.
6. **Under flag 4, character keys sent as `CSI u` report their alternate keys**: `CSI code : shifted : base ; modifiers u`, where the shifted key is the character that the key produced, given only with Shift and when it differs from the code, and the base key is the key of the base layout, given only when it is known and differs from the code (`CSI code :: base ; modifiers u` without a shifted key). Flag 4 changes no other key, and without flag 1 it changes nothing, since the legacy encoding has no `CSI u` forms.
7. **The keys of the numeric keypad follow NumLock**, as in kitty. `KeyEventHandler` passes the digits and the decimal point with NumLock off as the keypad's navigation keys (Keypad Insert, End, Down, Page Down, Left, Begin, Right, Home, Up, Page Up, and Delete). Under flag 1, a keypad key that produces text, a digit with NumLock on or an operator, sends its character, as text, when neither Ctrl, Alt, nor Meta is held, and otherwise `CSI u` with the protocol's number for it (57399 to 57415); the navigation keys and Keypad Enter, which produce no text, always send `CSI u` with their numbers (57417 to 57427, and 57414). DECKPAM is not consulted. Without the flags, the encoding ignores NumLock as before: a navigation key sends what the digit at its place sends.
8. **Enter without modifiers still follows LNM**, sending CR LF when it is set. kitty has no LNM; the legacy bytes of Enter are kept whole.
9. **The limit of [0005](0005-key-bytes-through-gate.md) that the gate sends only what xterm encodes is replaced**: `HostWriter.sendKey` sends what xterm encodes, or what flags 1 and 4 of the kitty keyboard protocol encode, for a key, its modifiers, and the terminal modes. The encoder's inputs are still enums, booleans, and the code points of a character key, and in the `CSI u` forms the code points are written in decimal digits, so no text from the host can reach the output. A program that leaves the flags set changes the bytes of keys for the programs after it, such as Ctrl+C for the shell, as in kitty; Enter, Tab, and Backspace without modifiers keep working, so that the user can type `reset`. The reply to `CSI ? u` is built from the flags, as the other replies are from the state.

## Alternatives considered

- **Every flag**: The protocol encourages terminals to implement all of them. vtfx cannot without a `KeyStroke` that describes releases and a path for typed characters that bypasses the IME editing model, which soft keyboards could not use anyway.
- **Keep all the flags that the program sets, and act only on those supported**: The reply to `CSI ? u` would claim flags that vtfx ignores, and the program could not detect it.
- **Flag 1 alone, with the character in lower case as the code**: Needs no change to `KeyStroke`, and lower case undoes Shift and Caps Lock for letters, but Ctrl+Shift+1 would be `CSI 33 ; 6 u`, which no other terminal sends, and programs could not match shortcuts across layouts.
- **The key of the base layout from the key code**: Android names key codes after a US keyboard, but the key character maps of other layouts may map scan codes to other key codes, so the key code does not always tell the place of the key.
- **DECSTR keeping the stacks, as in Ghostty, WezTerm, Windows Terminal, and iTerm2; `CSI < 0 u` popping one entry, as in Alacritty, xterm.js, foot, and iTerm2**: kitty, which defines the protocol, does otherwise.
- **The keypad following DECKPAM rather than NumLock**: No other terminal consults DECKPAM in the protocol, and kitty does not implement DECKPAM.
- **An option of the app to turn the protocol off**: WezTerm and xterm.js turn it off by default, and Windows Terminal has an option. The host turns it on, a program that exits without popping leaves Enter, Tab, and Backspace working, and nothing has asked for the option yet.
- **xterm's modifyOtherKeys instead**: Stays within what xterm encodes, but does not tell Esc apart and has no query; it was not asked for.
- **Keypad Enter as Enter**: Would keep Keypad Enter usable after a program left the flags set, but differs from kitty for a key that phones rarely have.

## Impact of reversing

- To drop the protocol: remove the stacks and the flags of `TerminalModes` from `Emulator`, the query from `TerminalQuery` and `Replies`, and the protocol's encoding from `KeyEncoder`; the limit of 0005 to xterm's encoding holds again. The unshifted key and the key of the base layout in `KeyStroke.Character`, and the keypad's navigation keys in `TerminalKey`, are public API, and removing them breaks apps.
- To support more flags: add them to the flags that the stacks keep, the modes, and `KeyEncoder`; flag 2 needs releases in `KeyStroke`, and flags 8 and 16 need typed characters sent as keys.
