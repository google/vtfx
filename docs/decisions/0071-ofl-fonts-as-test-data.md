# Fonts under the SIL Open Font License as test data

- Status: Approved (2026-10-23, decided by a human in a review of the review queue; the fonts and the download through Gradle chosen by a human on the proposal of an agent; running the test in `check.sh` chosen by an agent)
- Date: 2026-10-23
- Related: [0040](0040-sanitized-user-fonts.md) (item 10), [0035](0035-dependency-verification.md), [0018](0018-distribution.md), [0060](0060-artifacts-ship-only-checked-classes.md), section 10 of [fonts.md](../design/fonts.md), `ThirdPartyFontsTest` in `vtfx-font`

## Background

The gating tests of `vtfx-font` used only fonts generated by test code, because using third-party font files needed a human to check their licenses ([0040](0040-sanitized-user-fonts.md), item 10). Real fonts were checked only outside `check.sh`, on the emulator with the system's own fonts. The generated fonts cover the structures that the readers know, but not the sizes and the combinations of real CJK fonts.

The candidates were Noto Sans Mono CJK JP, the Noto Sans CJK collection, Sarasa Gothic, BIZ UDGothic, and HackGen, under the SIL Open Font License 1.1, and DejaVu Sans Mono, which is under the Bitstream Vera license instead. One weight of each CJK font is 5 to 20 MB, and git compresses font files hardly at all.

## Decision

1. **Fonts under the SIL Open Font License may be used as test data** (decided by a human); fonts under other licenses may not.
2. **They are never part of the distributed libraries** (decided by a human): no published artifact contains them, and no main source set refers to them.
3. **The build downloads them rather than the repository holding them** (decided by a human): they would make every clone tens of megabytes larger. They are Gradle dependencies of a configuration of `vtfx-font` that is on no classpath, fetched from an Ivy repository on `raw.githubusercontent.com` that serves only their groups, at pinned commits, and `gradle/verification-metadata.xml` pins their checksums as it does those of every other dependency ([0035](0035-dependency-verification.md)). Gradle caches them, so the network is needed only where the other dependencies are not cached either. The test task gets their paths as system properties.
4. **Three fonts, one of each kind of font file** (chosen by a human): BIZ UDGothic (TrueType), Noto Sans JP (CID-keyed CFF), and the Noto Sans CJK collection of the Regular weight (a collection of CID-keyed CFF faces), 29 MB in all.
5. **`ThirdPartyFontsTest` runs in `check.sh`** (chosen by an agent), as part of the unit tests of `vtfx-font`: each font must be read, and each sanitized face must be one that the verifier accepts and that sanitizing leaves as it is.

## Alternatives considered

- **Commit the fonts under `third_party/`**, as [0018](0018-distribution.md) keeps third-party material: about 30 MB in every clone, for three fonts, and more for each one added.
- **Download them in the test code**: the test would need its own checksums, cache, and proxy settings, a way into the build that dependency verification does not cover.
- **Run the test outside `check.sh`**, like long fuzzing: the gate would not see a change that breaks real fonts, and the download costs nothing more once Gradle has cached the fonts.
- **Keep only generated fonts in the gating tests**: real fonts would be checked only on the emulator.

## Impact of reversing

Remove the `thirdPartyFonts` configuration and its dependencies from `vtfx-font/build.gradle.kts`, the repository from `settings.gradle.kts`, their entries from `gradle/verification-metadata.xml`, and `ThirdPartyFontsTest`.
