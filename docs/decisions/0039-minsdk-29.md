# Lower minSdk to 29

- Status: Approved (2026-10-21, approved by a human, with the gaps on API 29 to 33 after the checks in [research/ime-gboard-api29.md](../research/ime-gboard-api29.md); minSdk 29 decided by a human on 2026-10-19)
- Date: 2026-10-19
- Related: Requirement 6.1, 6.3, 6.4, section 7 of [architecture.md](../design/architecture.md), sections 3 and 6 of [ime-contract.md](../design/ime-contract.md), [research/minsdk-2026-10.md](../research/minsdk-2026-10.md), [0006](0006-gate-defaults.md), [0008](0008-ime-view-and-selection.md), [0014](0014-performance.md), [0015](0015-accessibility.md), [0017](0017-ime-scope.md)

## Background

minSdk started at 34 because `InputConnection.replaceText`, which the IME contract uses, was added in API 34. Requirement 6.4 leaves minSdk to a trade-off per feature. A study of supporting older devices ([research/minsdk-2026-10.md](../research/minsdk-2026-10.md)) found:

- **The code**: below 29, the line cache of [0014](0014-performance.md) (`RenderNode`) and the underline metrics need a second path; below 26, so do `java.util.Base64` and disabling personalized learning (section 3 of ime-contract.md). From 29, only two IME calls newer than 29 need guarding, and from 31 none.
- **IME edits**: below 34, IMEs do not call `replaceText` and correct text through other calls. The contract has paths for these (section 6.1 of ime-contract.md, and decision 2 of [0008](0008-ime-view-and-selection.md)), but no IME was measured on those versions.
- **Accessibility**: below 34, the sensitive mark on the rows ([0015](0015-accessibility.md)) has no effect: the libraries treat every request as coming from an accessibility tool.
- **Clipboard**: the OS shows a preview of the clipboard on each copy from API 33, which [0006](0006-gate-defaults.md) relied on to let the user notice a rewrite by OSC 52, and notifies the user of reads from API 31. From API 29, only the focused foreground app can read the clipboard, as the KDoc of `AndroidClipboard.read` says.

The trade-off per level:

- 26 is the lowest level that keeps personalized learning disabled (section 3 of ime-contract.md).
- 29 also removes the fallback of the renderer, so the line cache of [0014](0014-performance.md) works on every supported version, and keeps clipboard reads foreground-only.
- 31 needs no fallback in the code at all.
- 33 keeps the clipboard preview that [0006](0006-gate-defaults.md) relies on.
- 34 keeps everything; any level below 34 loses the measured IME behavior and the sensitive mark.

## Decision

**minSdk is 29 (Android 10)** (decided by a human). Below 34, the following are accepted.

1. **IME edits on API 29 to 33** go through the paths of the contract other than `replaceText`. They are to be verified with traces recorded on those versions; until then, they are verified by the unit tests of `ImeEditor`, the Robolectric tests of `TerminalInputConnection` at SDK 29, and, on API 29, by the bytes that Gboard sent ([research/ime-gboard-api29.md](../research/ime-gboard-api29.md)).
2. **The rows are visible to every accessibility service on API 29 to 33**, not only to tools such as TalkBack. On API 34 and later, the sensitive mark of [0015](0015-accessibility.md) works as before. Nothing in vtfx can tell a tool from another service below 34. The alternatives (not exposing the rows below 34, or guessing from the list of enabled services) would break TalkBack (requirement 6.3) or shut out other screen readers. Section 6 of [usage.md](../usage.md) says so, so that apps that show secrets can decide, for example by not supporting those versions.
3. **The clipboard on API 29 to 32** has no copy preview, and on API 29 and 30 no notice of reads. Reads stay denied by default, and written content stays unmarked (not sensitive). Without the preview the user cannot notice a rewrite by OSC 52, so writes are denied by default as well ([0006](0006-gate-defaults.md)).

The code keeps one path wherever the platform allows it: the two IME calls newer than 29 are guarded in `TerminalInputConnection` (`setInitialSurroundingText`, API 30, in section 3 of [ime-contract.md](../design/ime-contract.md); `getSurroundingText`, API 31, in section 6.2). On API 29, the IME gets the input history by asking, with `getTextBeforeCursor` and the other queries in section 6.2. `SurroundingText` is constructed in a nested object annotated `@RequiresApi(31)`, as androidx does, so that the code that the verifier of an older runtime cannot resolve is outside `TerminalInputConnection`.

## Alternatives considered

- **Keep 34**: no work and no gap, but devices on Android 10 to 13 cannot use vtfx.
- **26**: also covers Android 8 and 9, which are a small share of devices. Needs a second drawing path without `RenderNode` (slower, and checked only on the emulator, since Robolectric draws without hardware acceleration) and font-independent underline metrics, and lets the app read the clipboard from the background on API 26 to 28 when the app allows reads.
- **31**: no fallback in the code, but devices on Android 10 and 11 cannot use vtfx, and the IME and accessibility gaps below 34 remain anyway.
- **33**: keeps the clipboard preview of [0006](0006-gate-defaults.md), with the same IME and accessibility gaps.
- **24**: also needs `Base64` replaced (core library desugaring was ruled out: it would make every app enable desugaring), and personalized learning cannot be disabled on API 24 and 25.
- **`EditorInfoCompat` for the initial surrounding text**: It would make androidx.core a direct dependency of `vtfx-compose` for one call (requirement 6.5).

## Impact of reversing

Going back to 34: restore `minSdk = 34` in `vtfx.android-library` and `vtfx.android-application` in `build-logic`, remove the version checks in `TerminalInputConnection` and the tests at `MIN_SDK`, and update section 7 of architecture.md, README.md, sections 1 and 6 of usage.md, and sections 3 and 6 of ime-contract.md. Going lower than 29 needs the fallbacks of the renderer, and a new look at the clipboard and personalized learning.
