# Lower minSdk to 29

- Status: Provisional (2026-10-19, minSdk 29 decided by a human; the work below is not done yet)
- Date: 2026-10-19
- Related: Requirement 6.1, 6.3, 6.4, section 7 of [architecture.md](../design/architecture.md), sections 3 and 6 of [ime-contract.md](../design/ime-contract.md), [0006](0006-gate-defaults.md), [0008](0008-ime-view-and-selection.md), [0014](0014-performance.md), [0015](0015-accessibility.md), [0017](0017-ime-scope.md), [0035](0035-dependency-verification.md)

## Background

minSdk started at 34 because `InputConnection.replaceText`, which the IME contract uses, was added in API 34 (section 7 of architecture.md). Requirement 6.4 leaves minSdk to a trade-off per feature. Supporting older devices was studied on 2026-10-19, with these findings.

### What the build needs below 34

Lint was run with the minSdk of the Android conventions lowered, on a copy of the tree. The JVM modules (`vtfx-core`, `vtfx-input`, `vtfx-gate`, `vtfx-session`) were included by compiling their main sources in a scratch Android library, because lint does not check Android API levels in JVM modules. The dependencies (Compose UI and Foundation 1.12.1, activity-compose 1.13.0, androidx.core 1.18.0) all have minSdk 23.

| API | Use | Where |
|---|---|---|
| 26 | `java.util.Base64` | OSC 52 in `Emulator` (`vtfx-core`) and `TerminalGate` (`vtfx-gate`) |
| 26 | `EditorInfo.IME_FLAG_NO_PERSONALIZED_LEARNING` | `TerminalInputConnection.configure` |
| 29 | `RenderNode`, `Canvas.drawRenderNode` | `LineCache` and `TerminalRenderer.draw` |
| 29 | `Paint.underlineThickness`, `Paint.underlinePosition` | `TerminalRenderer` |
| 30 | `EditorInfo.setInitialSurroundingText` | `TerminalInputConnection.configure` |
| 31 | `SurroundingText` | `TerminalInputConnection.getSurroundingText` |

With minSdk 29, lint reports only the two uses at API 30 and 31, all in `vtfx-compose`; the JVM modules and `vtfx-gate-android` report nothing, and the sample app builds (`assembleDebug`).

Overrides of methods added later (`replaceText` (34), the `TextAttribute` overloads (33), `requestCursorUpdates(int, int)` (33), `getSurroundingText` (31), `setImeConsumesInput` (31)) are not lint errors; older platforms do not call them.

### What the platform stops guaranteeing below 34

- **IME edits**: Before API 34, IMEs do not call `replaceText`. They correct text with `setComposingRegion`, `setSelection`, or `deleteSurroundingText` followed by `commitText`. The contract has paths for these (section 6.1 of ime-contract.md, and decision 2 of [0008](0008-ime-view-and-selection.md)), but no IME was measured on those versions: every trace in `tools/ime-probe/traces/` was recorded on API 36 or 37.
- **Accessibility**: the sensitive mark on the rows ([0015](0015-accessibility.md)) has no effect. This was confirmed in the class files: `AndroidComposeViewAccessibilityDelegateCompat` (Compose UI 1.12.1) hides sensitive nodes from requests that `AccessibilityManagerCompat.isRequestFromAccessibilityTool` says are not from a tool, and that method (androidx.core 1.18.0) returns `true` below API 34. `AccessibilityNodeInfoCompat.setAccessibilityDataSensitive` only stores the flag in the extras below 34.
- **Clipboard**: the OS shows a preview of the clipboard on each copy from API 33, on which [0006](0006-gate-defaults.md) relies to let the user notice a rewrite by OSC 52. The OS notifies the user of clipboard reads from API 31. The OS lets only the focused foreground app read the clipboard from API 29, as the KDoc of `AndroidClipboard.read` says.

### The trade-off per level

- 26 is the lowest level that keeps personalized learning disabled (section 3 of ime-contract.md).
- 29 also removes the fallback of the renderer, so the line cache of [0014](0014-performance.md) works on every supported version, and keeps clipboard reads foreground-only.
- 31 needs no fallback in the code at all.
- 33 keeps the clipboard preview that [0006](0006-gate-defaults.md) relies on.
- 34 keeps everything; any level below 34 loses the measured IME behavior and the sensitive mark.

## Decision

**minSdk is 29 (Android 10)** (2026-10-19, decided by a human). Below 34, the following are accepted.

1. **IME edits on API 29 to 33** go through the paths of the contract other than `replaceText`. They are verified with traces recorded on those versions (the follow-up work below). Until then, they are verified only by the unit tests of `ImeEditor`.
2. **The rows are visible to every accessibility service on API 29 to 33**, not only to tools such as TalkBack. On API 34 and later, the sensitive mark of [0015](0015-accessibility.md) works as before. Nothing in vtfx can tell a tool from another service below 34. The alternatives (not exposing the rows below 34, or guessing from the list of enabled services) would break TalkBack (requirement 6.3) or shut out other screen readers. Section 6 of [usage.md](../usage.md) says so, so that apps that show secrets can decide, for example by not supporting those versions.
3. **The clipboard on API 29 to 32** has no copy preview, and on API 29 and 30 no notice of reads. The defaults of the gate do not change: reads stay denied by default, and writes stay unmarked ([0006](0006-gate-defaults.md)).

The code keeps one path wherever the platform allows it.

| API | Behavior on older versions |
|---|---|
| 30 | `TerminalInputConnection.configure` calls `setInitialSurroundingText` only on API 30 and later. On API 29, the IME gets the input history by asking, with `getTextBeforeCursor` and the other queries in section 6.2 of the contract. `EditorInfoCompat` is not used: it would make androidx.core a direct dependency of `vtfx-compose` for one call (requirement 6.5). |
| 31 | `getSurroundingText` is annotated `@RequiresApi(31)`, and the `SurroundingText` is constructed in a nested object annotated the same way, as androidx does, so that the code that the verifier of an older runtime cannot resolve is outside `TerminalInputConnection`. On older versions, the platform does not call the method. |

## Work

The work is done by an agent in the order below. Each commit passes `scripts/check.sh`. The first does not change behavior on API 34 and later; it comes before the minSdk change, which otherwise fails lint.

### 1. `compose: Guard IME APIs newer than 29`

- Make the two changes in the table above in `TerminalInputConnection`.
- Add `const val MIN_SDK = 29` next to `SDK` in `TestSdk.kt` of `vtfx-compose`, and Robolectric tests at `@Config(sdk = [MIN_SDK])`. They must fail before the change, with `NoSuchMethodError` from `setInitialSurroundingText`, and pass after it.
  - `configure` fills `EditorInfo` without `setInitialSurroundingText`.
  - Typing, committing, and deleting through `TerminalInputConnection` send what they send on the default SDK.
- Robolectric 4.17 supports SDK 29 (it lists SDK 23 and later). It downloads the `android-all` jar of SDK 29 on the first run, outside Gradle's dependency verification, as for SDK 36 (see the open item about Robolectric's jars in the review queue).

### 2. `build: Lower minSdk to 29`

- In `build-logic/src/main/kotlin/vtfx.android-library.gradle.kts` and `vtfx.android-application.gradle.kts`, set `minSdk = 29`, and replace the comment that gives API 34 and `replaceText` as the reason with a reference to this decision. `build-logic/` is under `security_review` in `config/protected-paths.toml`: keep the change to these lines, and say in the commit message why it is needed.
- Check with `./gradlew lintRelease` (the Android modules) that no `NewApi` or `InlinedApi` is reported.
- Update the documents to match:
  - Section 7 of [architecture.md](../design/architecture.md): minSdk is 29, with the reason and a link to this decision, replacing the paragraph about API 34 and the note that the build still uses 34.
  - [README.md](../../README.md) and section 1 of [usage.md](../usage.md): "minSdk is 34" becomes 29.
  - Section 6 of [usage.md](../usage.md): below API 34, the rows are visible to every accessibility service (decision 2).
  - [ime-contract.md](../design/ime-contract.md): in section 3, the initial surrounding text is passed on API 30 and later; in section 6, only IMEs on API 34 and later call `replaceText`, and only those on API 31 and later call `getSurroundingText`.
  - Set the status line of this decision to say that the work is done, leaving the status Provisional.
- [review-queue.md](../review-queue.md): add the changes to `build-logic` to "Changes to protected paths" in section 2, and add to section 3 the IME checks on API 29 to 33 (autocorrect, the period of a double space, and reconversion in Japanese with Gboard; see the follow-up work).
- Do not change `REQUIREMENTS.md`. Its section 8 records the initial value, 34, as the initial value.

## Follow-up work

Not part of the change above. Each can be done separately.

- **IME traces on API 29 to 33**: lower the minSdk of `tools/ime-probe/app` (33) to 29, create AVDs of API 29, 31, and 33 with Gboard, and record the scenarios of `spec/ime/` there. Traces and spec files are owned by humans: put the proposed spec files in `spec-proposals/` and run them as agent-owned tests, and put adding the traces in the review queue (section 4 of [testing.md](../design/testing.md)). Whether the current Gboard installs on API 29 is not known yet.
- **Emulator e2e on API 29**: `scripts/emulator.sh` sets up one AVD. Running `scripts/e2e_ime.py` and `scripts/e2e_render.py` on an API 29 AVD as well is a report, not a gate.
- **A check of the Android APIs that the JVM modules use**: the study found none above 29 in `vtfx-core`, `vtfx-input`, `vtfx-gate`, and `vtfx-session`, but nothing in `scripts/check.sh` stops a later change from using a JDK API that Android 10 lacks. Candidates are lint over the main sources of the JVM modules in a scratch Android library, as in the study, or a signature check such as Animal Sniffer, which is a new dependency. Decide which in its own decision.

## Alternatives considered

- **Keep 34**: no work and no gap, but devices on Android 10 to 13 cannot use vtfx.
- **26**: also covers Android 8 and 9, which are a small share of devices. Needs a second drawing path without `RenderNode` (slower, and checked only on the emulator, since Robolectric draws without hardware acceleration) and font-independent underline metrics, and lets the app read the clipboard from the background on API 26 to 28 when the app allows reads.
- **31**: no fallback in the code, but devices on Android 10 and 11 cannot use vtfx, and the IME and accessibility gaps below 34 remain anyway.
- **33**: keeps the clipboard preview of [0006](0006-gate-defaults.md), with the same IME and accessibility gaps.
- **24**: also needs `Base64` replaced (core library desugaring was ruled out: it would make every app enable desugaring), and personalized learning cannot be disabled on API 24 and 25.

## Impact of reversing

Going back to 34: restore `minSdk = 34` and its comment in the two conventions, remove the version checks in `TerminalInputConnection` and the tests at `MIN_SDK`, and revert the documents listed under "Work". Going lower than 29 needs the fallbacks of the renderer in the table of the background, and a new look at the clipboard and personalized learning.
