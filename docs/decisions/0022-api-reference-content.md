# Content of KDoc in the API reference

- Status: Approved (2026-10-15, approved by a human in a review of the review queue)
- Date: 2026-10-14
- Related: "API reference" in [0016](0016-public-api.md), requirement 6.5 (documenting the contract of the public API), `scripts/check_kdoc.py`

## Background

The KDoc of the public API appears as is in the HTML API reference generated by Dokka ([0016](0016-public-api.md)). The readers of the reference are developers of apps embedding vtfx, who do not necessarily read this repository's documents.

However, the KDoc of the public API referred to documents and files in the repository, such as `(docs/decisions/0019)`, `(requirement 6.1: spoofed links)`, `(docs/design/architecture.md section 3.4)`, and `scripts/gen_char_width.py`. In the reference, these do not become links and point to documents readers cannot open. The decision records and design documents were written in Japanese, so readers of the English reference might not be able to read them either. Some, like `docs/decisions/0002`, left default values to the referenced document and did not write them in the KDoc.

Similarly, the KDoc of `CellStyle` explained the bit layout of the `Long`, and the KDoc of `CharWidth` the name of the script that generates the table. Both are implementation details invisible to apps.

## Decision

- KDoc that appears in the reference (public declarations not excluded with `@suppress`) does not refer to documents or files in the repository. The contract is complete within the KDoc.
- References for maintainers (decision records, requirement sections, design documents) go in line comments (`//`) before the declaration or in comments in the implementation. They are kept only where the decision something is based on is not obvious.
- Implementation details (data representation, generation steps) are written in comments, not KDoc.
- `scripts/check_kdoc.py` checks that `docs/`, `scripts/`, and `requirement <number>` do not appear in KDoc that appears in the reference.
- KDoc of internal declarations (`@InternalVtfxApi`) and of `internal` and `private` declarations does not appear in the reference, so it may keep referring as before.
- Dokka 2.2 shows a nullable function type such as `onLinkClick: ((TerminalLinkClick) -> Unit)?` of `Terminal` without the parentheses, as `(TerminalLinkClick) -> Unit?`. This is accepted as a limitation of Dokka (2026-10-15, decided by a human): the API is not changed to work around it (a type alias would add to the public API), and the KDoc of such a parameter says in words that it may be null.

## Alternatives considered

- **Make references links to GitHub URLs**: They would be broken until the repository is published. The referenced documents were in Japanese, so many readers of the reference could not read them. A reference for each version would also point to the latest documents on `main`.
- **Keep the references and explain at the top of the reference that "references point to documents in the repository"**: Fewer changes, but it would still point to documents readers cannot open.
- **Just delete the references**: Maintainers could no longer trace from the code to the decision records.

## Impact of reversing

Put the references back into the KDoc and remove the check in `check_kdoc.py`. Only the presentation of the reference changes; there is no impact on the API.
