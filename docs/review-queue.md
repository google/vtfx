# Review queue

Items that need a human: decisions, work only humans can do, and checks on real devices. Agents add an item when they run into one, and remove it once it is resolved, after writing the outcome in the related decision or document. This file lists only open items; the outcomes live in [decisions/](decisions/README.md) and the design documents.

For each item, write what is needed, why the agent cannot do it, and links to the related decisions, documents, or code.

## 1. Decisions

Until decided, the provisional decision is implemented. The impact of reversing is in "Impact of reversing" of each decision.

| Item | What to decide | Related |
|---|---|---|
| Provisional decisions | Approve or revise the decisions whose status is "Provisional": [0033](decisions/0033-sticky-modifiers-and-composing-text.md) | [decisions/](decisions/README.md) |
| Boundary check against adversarial changes | When to make `scripts/check_boundaries.py` hold against changes written to get around it, not only against obvious mistakes: after publication (2026-10-15, decided by a human). Today it is a regex guardrail over source text (requirement 6.1 allows that in the initial phase). The gaps found in a security review (2026-10-14) were closed by extending it (Compose's clipboard and URL handler, `LinkAnnotation.Url`, `ShareCompat`, `javax.net`, `java.lang.invoke`, `DownloadManager`, and `project(...)` and `include(...)` written with named arguments, across lines, or with non-literal paths), but an API under a name not listed still gets through. Candidates: checking compiled classes or the resolved dependency graph instead of source text, and listing allowed APIs instead of forbidden ones | [architecture.md](design/architecture.md) section 5, `config/boundaries.toml`, `scripts/check_boundaries.py` |
| Robolectric's Android jars | Whether and how to verify the `android-all` jars that Robolectric downloads for the tests of the Android modules. Robolectric fetches them into `~/.m2` with its own downloader, outside Gradle, so `gradle/verification-metadata.xml` does not cover them ([0035](decisions/0035-dependency-verification.md)). Candidates: declare them as Gradle dependencies and run Robolectric offline from them, or keep relying on the repository | [0035](decisions/0035-dependency-verification.md), `build-logic` |
| API shape before 1.0 | Whether to change these parts of the public API before 1.0, after which each of the following changes breaks apps compiled earlier and needs a major version ([0016](decisions/0016-public-api.md)). Found in a review of binary compatibility (2026-10-16). Until decided, the API stays as it is. How parameters are added from 1.0 on is decided in [0036](decisions/0036-adding-parameters.md). (1) Data classes with public constructors among what vtfx returns: `TerminalModes`, `CursorState`, `Hyperlink`, `TerminalLink.Explicit` and `Matched`, `TerminalLinkClick`. A new property (a new mode; the position of a link click, which [0031](decisions/0031-desktop-pointer-and-terminal-state.md) foresees) changes the signatures of the constructor and `copy`, and callers compiled earlier get `NoSuchMethodError`. Hidden overloads (0036) can keep the previous constructor and `copy` (checked with Kotlin 2.4.21), but do not help with the rest: `componentN` fixes the order of the properties, `equals` and `toString` cover every property, and apps can build any state, which they do not need for what vtfx returns. An `internal` constructor alone does not hide `copy` (Kotlin 2.4 warns, an error with `allWarningsAsErrors`); `@ConsistentCopyVisibility` does, but leaves `componentN` public. Candidates: classes with internal constructors and hand-written `equals`, `hashCode`, and `toString`, like `TerminalSnapshot`. (2) Public `const val`s are copied into apps at compile time. `TerminalLimits.MAX_DIMENSION`, `MAX_SCROLLBACK_LINES`, and `MAX_STRING_LENGTH` bound arguments that vtfx checks with `require`, so lowering one makes apps compiled earlier throw `IllegalArgumentException`; `CharWidth.UNICODE_VERSION` reports the version an app was compiled with, not that of the tables it runs with. Candidates: plain `val`s, or committing to the values. (3) Whether adding an entry to an enum, or a subtype to a sealed type, that vtfx hands to apps is a breaking change under 0016: an exhaustive `when` compiled earlier throws `NoWhenBranchMatchedException` on it. Kotlin has no marker for a non-exhaustive type (like Rust's `#[non_exhaustive]` or Swift's `@unknown default`), so libraries choose per type: a closed set whose growth needs a major version (Compose's `LayoutDirection`), a value class with constants in its companion, on which `when` needs `else` (Compose's `PointerType`, `TextAlign`), or an entry for unknown values. Types that apps give to vtfx (`TerminalKey`, `KeyStroke`, `TerminalFont`, `AmbiguousWidth`) can grow without breaking apps. Of those that vtfx returns, `TerminalLink` (new kinds of links) and `MouseEncoding` (SGR-Pixels, mode 1016) are likely to grow; `UnderlineStyle` (SGR 4:0 to 4:5), `CursorShape` (DECSCUSR), and `MouseTracking` are nearly closed. Candidates: declare in 0016 which types are closed, make the growing ones open, or stop exposing what apps do not need (whether the host asks for the mouse may be enough instead of `MouseTracking` and `MouseEncoding`) | [0016](decisions/0016-public-api.md), [0031](decisions/0031-desktop-pointer-and-terminal-state.md), [0036](decisions/0036-adding-parameters.md), requirement 6.5 |

## 2. Work only humans can do

| Item | Contents | Related |
|---|---|---|
| Publishing | The repository https://github.com/google/vtfx was published on 2026-10-15 with version 0.1.0 ([0018](decisions/0018-distribution.md)). Open: tagging the published commit `v0.1.0`, if not done yet (the source links of the API reference point at that tag); setting up Maven Central (the publishing configuration and the permission for `com.google.vtfx`); how versions after 0.1.0 are numbered; when to go to 1.0; and how apps get the six artifacts at one version. The artifacts call each other's `@InternalVtfxApi` declarations, which may change in any version ([0016](decisions/0016-public-api.md)), and vtfx-compose copies the constant `TerminalLimits.MAX_DIMENSION` at compile time, so a Gradle resolution that mixes versions (for example `vtfx-session` raised by another dependency of the app) can fail with `NoSuchMethodError` or a wrong bound. Candidates: a BOM, or dependency constraints between the artifacts in the published metadata (found in a review of binary compatibility, 2026-10-16) | [0018](decisions/0018-distribution.md), [0016](decisions/0016-public-api.md) |
| Changes to protected paths | Review the changes to the paths under `security_review` in `config/protected-paths.toml` made after the last review (the whole tree, 2026-10-15): `build-logic/src/main/kotlin/vtfx.screenshot-test.gradle.kts` passes the directories of the screenshot goldens to the tests ([0034](decisions/0034-official-screenshot-goldens.md)); `gradle.properties`, `vtfx.dokka.gradle.kts`, and `vtfx.api-reference.gradle.kts` in `build-logic` set the version, the footer, and the source links of the API reference ([0016](decisions/0016-public-api.md)); `TerminalGate.isAllowedUrl` in `vtfx-gate` refuses default-ignorable characters, from the table `UnicodeDefaultIgnorables` generated from `third_party/unicode`, and userinfo in `http` and `https` URLs ([0006](decisions/0006-gate-defaults.md)), and `vtfx.ktfmt.gradle.kts` in `build-logic` leaves that generated table unformatted; `config/boundaries.toml`, `scripts/check_boundaries.py`, and its tests close the gaps of the guardrail found in a security review (item "Boundary check against adversarial changes" above); `gradle/verification-metadata.xml` adds dependency verification ([0035](decisions/0035-dependency-verification.md)) | `config/protected-paths.toml`, section 5 of [architecture.md](design/architecture.md) |

## 3. Checks on real devices

Things that could not be checked on the emulator and the JVM. The steps, and what was already checked on the emulator, are in [device-checks.md](device-checks.md).

| Item | What to check | Related |
|---|---|---|
| IMEs other than Gboard, and direct input | With Samsung Keyboard, SwiftKey, and Simeji, whether Latin letters arrive one at a time, both by default and with `directInput`. Voice input and handwriting input | [0017](decisions/0017-ime-scope.md) |
| Rendering performance | Whether the frame time of rendering stays around 16 ms (the emulator's software GPU is not a guide) | [0014](decisions/0014-performance.md) |
| TalkBack | Moving by line, explore by touch, the keyboard appearing on a double tap, and input | [0015](decisions/0015-accessibility.md) |
| The input history on switching IMEs | Whether switching the IME in the middle of a line (from the IME's switch key or the system picker) resets the input history. `closeConnection` does not reset it, so if the window keeps the focus, the new IME gets the text typed with the previous one through `setInitialSurroundingText`. If it does, reset on `closeConnection` too. Found in a security review (2026-10-14) | `TerminalInputConnection`, 5.1 of [ime-contract.md](design/ime-contract.md) |
| Links taken by a protected activity | Whether `AndroidUrlOpener.open` throws `SecurityException` when the activity that takes the link (an app that verified the link's domain) requires a permission. It catches only `ActivityNotFoundException`, and `UrlOpener` must not throw, so the app would crash after the user confirms the link. Needs a second app with such an activity, which Robolectric does not model. Found in a security review (2026-10-14) | `AndroidUrlOpener`, `UrlOpener` |
| Han glyphs and locale | On devices with their own CJK font (Samsung and others), whether glyphs are Japanese with `LocaleList("ja")` (checked on the emulator) | [0011](decisions/0011-unicode.md) |
| Key interception | Whether `onPreImeKeyEvent` of `Terminal` receives the keys of a real physical keyboard before Gboard, in English and in Japanese. On the emulator, keys injected by `adb` reached it before Gboard, whereas `onPreviewKeyEvent` never saw them | [0032](decisions/0032-keys-and-layout.md), 3.1 of [device-checks.md](device-checks.md) |
| Mouse and touchpad | On a Chromebook, Samsung DeX, or a tablet with a Bluetooth mouse: wheel scrolling (including a high-resolution wheel and two-finger touchpad scrolling), drag, double and triple click selection, Shift+click, right click (the menu at the pointer), and the I-beam and hand pointer icons; with the host asking for the mouse, the reports. Whether a touchpad's taps and moves arrive as `PointerType.Mouse` or as touch, and whether the right button reaches the app rather than acting as Back. Whether a click shows the software keyboard with a hardware keyboard attached. Compose's injected mouse events on Robolectric are all that was checked | [0031](decisions/0031-desktop-pointer-and-terminal-state.md), `TerminalMouse`, section 7 of [device-checks.md](device-checks.md) |
| Copying all the text | Whether Select all and Copy, with a full scrollback of long lines (256 Ki characters copied), reaches the system clipboard and its preview without `TransactionTooLargeException`, and how long it takes on the main thread. Robolectric's clipboard has no Binder limit | [0031](decisions/0031-desktop-pointer-and-terminal-state.md), `TerminalDisplay.selectedText` |
| AltGr on physical keyboards | With layouts such as German, whether characters typed with AltGr (`@` for `AltGr+Q`, `{`, and so on) arrive, rather than ESC and a letter. `KeyEventHandler` sends Alt as an ESC prefix and does not distinguish right Alt. If they do not arrive, the fix is to prefer the character when the layout produces one with right Alt | `KeyEventHandler` in `vtfx-compose`, 6.3 of [ime-contract.md](design/ime-contract.md) |
