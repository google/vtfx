## R1: `CanonicalVerifier` in `vtfx-font-gate` does not bound variation sequences to `2^20`

- Related: [CanonicalVerifier.kt](../../vtfx-font-gate/src/main/kotlin/com/google/vtfx/font/gate/CanonicalVerifier.kt) (`checkFormat14`, `checkDefaultTable`, `checkNonDefaultTable`), [CmapReader.kt](../../vtfx-font/src/main/kotlin/com/google/vtfx/font/CmapReader.kt) (`variationSelectors`, `MAX_VARIATION_SEQUENCES`), [FontFuzzer.kt](../../vtfx-font/src/fuzz/kotlin/com/google/vtfx/font/FontFuzzer.kt) (`fuzzerTestOneInput`)
- Contract:
  - Section 9 of [fonts.md](../design/fonts.md): "Variation sequences, all selectors together: `2^20` (`TooComplex`)".
  - Section 6 of [fonts.md](../design/fonts.md): "every byte of the file is either checked against a fixed value, checked against a value computed from other parts of the file, or a number within a checked range; so a canonical font is what sanitizing it gives."
  - Section 10 of [fonts.md](../design/fonts.md) and `FontFuzzer.kt`: any byte array accepted by `SanitizedFont.fromCanonical` must be accepted by `FontFile.sanitize` and left unchanged.
- Reproduction tests: `r1a_canonicalVerifierRejectsMoreThanMaxVariationSequences`, `r1b_canonicalFontAcceptedByVerifierIsAcceptedBySanitize`

Steps:

1. Construct a 17 KB canonical font whose `cmap` Format 14 subtable has one variation selector (`U+FE00`) with 4,097 canonical Default UVS ranges of 256 code points each (`0xE000 + r * 256` with `additionalCount = 255`), totaling `4,097 * 256 = 1,048,832` variation sequences (`> 2^20 = 1,048,576`).
2. Pass the bytes to `SanitizedFont.fromCanonical(canonical, FontLimits())` (`r1a`).
3. Pass the accepted `SanitizedFont`'s bytes to `FontFile.sanitize(loaded.toByteArray(), 0, FontLimits())` (as `FontFuzzer.fuzzerTestOneInput` does at line 59; `r1b`).

Expected result: `SanitizedFont.fromCanonical` rejects the font with `InvalidFontException` (`Kind.Malformed`), and any font accepted by `SanitizedFont.fromCanonical` is accepted by `FontFile.sanitize` and returns equal bytes.

Actual result:

- `r1a`: `SanitizedFont.fromCanonical` succeeds and returns a `SanitizedFont` of 17,056 bytes (`Expected an exception of class com.google.vtfx.font.gate.InvalidFontException to be thrown, but was completed successfully`). Up to 260 variation selectors can pass ~289 million default variation sequences in ~4.5 MB through the gate to native code.
- `r1b`: `FontFile.sanitize` throws `com.google.vtfx.font.gate.InvalidFontException: more than 1048576 mapped code points` (`Kind.TooComplex`) on the font that `SanitizedFont.fromCanonical` accepted.

View of the cause: `CmapReader.variationSelectors()` in `vtfx-font` maintains a shared budget of `MAX_VARIATION_SEQUENCES = 1 shl 20` across all default UVS code points and non-default UVS mappings of all selectors, but `CanonicalVerifier.checkFormat14` in `vtfx-font-gate` only checks the structure and ordering of ranges and mappings without counting the total variation sequences across selectors.

Direction of the fix: Track the total number of variation sequences (`count + 1` for each Default UVS range and `1` for each Non-Default UVS mapping across all selector records) in `CanonicalVerifier.checkFormat14` and reject when the total exceeds `2^20` (`1 shl 20`). Check both default ranges and non-default mappings, and sums across multiple selectors.

## R2: Total glyph points across a face are not bounded in `vtfx-font` or `vtfx-font-gate`

- Related: [CanonicalWriter.kt](../../vtfx-font/src/main/kotlin/com/google/vtfx/font/CanonicalWriter.kt) (`write`, `writeGlyph`), [GlyfOutlines.kt](../../vtfx-font/src/main/kotlin/com/google/vtfx/font/GlyfOutlines.kt) (`outline`, `appendSimple`), [CffOutlines.kt](../../vtfx-font/src/main/kotlin/com/google/vtfx/font/CffOutlines.kt) (`outline`, `QuadraticPen`), [CanonicalVerifier.kt](../../vtfx-font-gate/src/main/kotlin/com/google/vtfx/font/gate/CanonicalVerifier.kt) (`checkGlyf`, `checkGlyph`)
- Contract:
  - Section 9 of [fonts.md](../design/fonts.md): "`FontLimits.maxOutputBytes`: the canonical font, which also bounds the points of the whole font" and "The limits of one glyph alone do not bound the time of a face, since every glyph can reach them through subroutines or composite glyphs that all the glyphs share, in a few bytes each; so the work of the whole face is bounded too, independently of the number of glyphs."
- Reproduction tests: `r2a_pointsAcrossAllGlyphsOfAFaceAreBoundedInSanitize`, `r2b_pointsAcrossAllGlyphsOfAFaceAreBoundedInCanonicalVerifier`

Steps:

1. Build a 164 KB TrueType font where glyph 1 is a 144-byte simple glyph of `16,384` `(0, 0)` points encoded with 64 repeat-flag pairs (`[0x39, 0xFF]`: 256 points per 2 bytes and 0 coordinate bytes), and 8,192 composite glyphs each reference glyph 1 once (`8,192` components visited total, far below `MAX_FACE_COMPONENTS = 2^22`, and `1.24 MB` canonical output size, far below `maxOutputBytes = 64 MiB`). Across the face, the 8,193 non-empty glyphs contain `8,193 * 16,384 = 134,234,112` (`> 2^27`) points (and with 65,533 composite glyphs in a 1.3 MB input / 9.7 MB canonical output, `1,073,709,056` points).
2. Call `FontFile.sanitize(font, 0, FontLimits())` (`r2a`).
3. Pass the resulting 1.24 MB canonical font to `SanitizedFont.fromCanonical(canonical, FontLimits())` (`r2b`).

Expected result: Both `FontFile.sanitize` (`Kind.TooComplex`) and `SanitizedFont.fromCanonical` (`Kind.Malformed`) reject a face whose total points across all glyphs exceed the face point budget.

Actual result: Both `FontFile.sanitize` and `SanitizedFont.fromCanonical` accept the font after iterating over all `134,234,112` points (and up to `1,073,725,440` points in a 9.7 MB canonical font).

View of the cause: Section 9 of `fonts.md` assumes `FontLimits.maxOutputBytes` bounds the total points of the whole font. However, in both TrueType `glyf` and the canonical `glyf` encoding, runs of points with `(dx = 0, dy = 0)` use the `REPEAT` flag (`0x08`) with `X_SAME` (`0x10`) and `Y_SAME` (`0x20`), packing 256 points into 2 bytes (128 points per byte). Consequently, a glyph of `16,384` points takes only 144 bytes in `glyf`, and 65,535 glyphs can pack over 1.07 billion points into 9.7 MB (while Noto Serif CJK has only ~5 million points across 65,535 glyphs).

Direction of the fix: Bound the total points across all glyphs of a face in both `vtfx-font` (covering both `GlyfOutlines` and `CffOutlines` / `CanonicalWriter`) and `CanonicalVerifier` in `vtfx-font-gate` with the same limit, so that `CanonicalVerifier` and `FontFile.sanitize` remain in agreement and document the limit in section 9 of `fonts.md`.

## R3: `CffFont.checkFontMatrix` accepts CFF fonts whose `FontMatrix` does not scale by `1/unitsPerEm`

- Related: [Cff.kt](../../vtfx-font/src/main/kotlin/com/google/vtfx/font/Cff.kt) (`CffFont.read`, `checkFontMatrix`)
- Contract:
  - Section 4 of [fonts.md](../design/fonts.md): "A `CFF ` table that uses the following is rejected as unsupported, because real fonts do not use them or because another table has the authoritative value: ... a `FontMatrix` other than a scale of 1/`unitsPerEm` or the identity (which CID-keyed fonts give in the Top DICT or the Font DICTs, the other holding the scale)" and "Values out of range ... are rejected as unsupported, not clamped, so that no font is drawn differently from what its maker meant without a word."
- Reproduction tests: `r3a_nameKeyedCffWithIdentityFontMatrixIsUnsupported`, `r3b_cffWithUnitsPerEmOtherThan1000AndDefaultFontMatrixIsUnsupported`, `r3c_cidKeyedCffWithoutEmScaleInEitherDictIsUnsupported`

Steps:

1. `r3a`: Call `FontFile.sanitize` on a name-keyed CFF font with `unitsPerEm = 1000` and Top DICT `FontMatrix = [1, 0, 0, 1, 0, 0]` (identity).
2. `r3b`: Call `FontFile.sanitize` on a name-keyed CFF font with `unitsPerEm = 2048` and no `FontMatrix` in the Top DICT (so CFF's default `[0.001, 0, 0, 0.001, 0, 0]` = `1/1000` applies instead of `1/2048`).
3. `r3c`: Call `FontFile.sanitize` on a CID-keyed CFF font with `unitsPerEm = 2048`, Top DICT `FontMatrix = [1, 0, 0, 1, 0, 0]`, and no `FontMatrix` in the Font DICT (so neither DICT holds `1/2048`).

Expected result: All three are rejected with `InvalidFontException` of `Kind.Unsupported`.

Actual result: All three are accepted by `FontFile.sanitize` (`Expected an exception of class com.google.vtfx.font.gate.InvalidFontException to be thrown, but was completed successfully`).

View of the cause: `CffFont.checkFontMatrix` inspects each DICT in isolation, returns immediately if `FONT_MATRIX` is absent (`?: return`), and accepts either `scale == 1/unitsPerEm` or `scale == 1.0` regardless of whether the font is name-keyed or CID-keyed and regardless of what the other DICT contains.

Direction of the fix:
- For a name-keyed CFF font, require the Top DICT's effective `FontMatrix` (defaulting to `[0.001, 0, 0, 0.001, 0, 0]` when omitted) to be a uniform scale of `1/unitsPerEm` (not the identity).
- For a CID-keyed CFF font, check the combined effect of the Top DICT and each Font DICT (where one holds `1/unitsPerEm` and the other the identity, taking CFF defaults into account: in CFF, an omitted Top DICT `FontMatrix` defaults to `0.001` and an omitted Font DICT `FontMatrix` defaults to `0.001`, or require one to be `1/unitsPerEm` and the other identity).

## Other observations (not counted as bugs in `vtfx-font` / `vtfx-font-gate`)

- **Defensive copy of `TerminalFont.Sanitized.families` and `MAX_FAMILIES` check in `SanitizedTypefaces.regular` and `FontStore`**:
  - In [TerminalFont.kt](../../vtfx-compose/src/main/kotlin/com/google/vtfx/compose/TerminalFont.kt) (`TerminalFont.Sanitized`), `public val families: List<SanitizedFamily>` stores the caller's list reference directly without copying it (`java.util.List.copyOf(families)`), unlike `TerminalColors.palette` (`TerminalStyle.kt:71`) and `GatePolicy.urlSchemes` (`Capabilities.kt:125`). If a caller mutates a `MutableList` after construction, `families.size in 1..MAX_FAMILIES` can be violated on an `@Immutable` type.
  - In [SanitizedTypefaces.kt](../../vtfx-font-gate-android/src/main/kotlin/com/google/vtfx/font/gate/android/SanitizedTypefaces.kt) (`SanitizedTypefaces.regular`), only `require(families.isNotEmpty())` is checked, not `families.size <= 64`.
  - In [FontStore.kt](../../vtfx-sample/src/main/kotlin/com/google/vtfx/sample/FontStore.kt) and [MainActivity.kt](../../vtfx-sample/src/main/kotlin/com/google/vtfx/sample/MainActivity.kt), `FontStore.import` and `FontStore.load` do not cap saved fonts at `TerminalFont.Sanitized.MAX_FAMILIES` (`64`), so importing a 65th font in `vtfx-sample` makes `TerminalFont.Sanitized(...)` throw `IllegalArgumentException` during composition.
- **Reusing `OutlineBuilder` across glyphs in `GlyfOutlines`**:
  - [Outline.kt](../../vtfx-font/src/main/kotlin/com/google/vtfx/font/Outline.kt) documents that `OutlineBuilder.build()` keeps its internal arrays so that one builder can collect the outlines of all glyphs of a font without growing its arrays again for each, as `QuadraticPen` in `CffOutlines` does, but [GlyfOutlines.kt](../../vtfx-font/src/main/kotlin/com/google/vtfx/font/GlyfOutlines.kt) (`outline`, line 51) allocates a new `OutlineBuilder` per glyph.
